When you run long prompts across multiple tabs, Ophel keeps tab titles informative, alerts you the moment an answer finishes, hides titles in public spaces, and optionally tracks local send counts and token estimates.

## Tab behavior and auto-renaming

Open **Settings → Features → Tab Settings**:

| Setting | Options | Default | Location & notes |
| --- | --- | --- | --- |
| **Open New Chat in New Tab** | On / Off | Off | Adds a quick **New Tab** button to the panel header that opens the current site in a new tab. |
| **Auto Rename Tab** | On / Off | On | Updates the browser tab title with the active chat title and model name. |
| **Show Status Icon** | On / Off | On | Prepends `⏳` while generating and `✅` when done. |
| **Refresh Interval** | 1 / 3 / 5 / 10 / 30 / 60 s | 3 s | **Advanced options** — Automatically slows to ≥ 15 s when the tab is idle in the background. |
| **Title Format** | Custom template | `{status}{title}->{model}` | **Advanced options** — Supports `{status}`, `{title}`, and `{model}` tokens (for example, `⏳ Architecture review->GPT-4o`). |
| **Hide checkmark when read** | On / Off | Off | **Advanced options** — Removes `✅` once you return to the tab. |

### Privacy mode

Located in the **Privacy Mode** card under **Settings → Features → Tab Settings**:

- **Privacy Mode** (default **Off**): Replaces the browser tab title with a neutral decoy title so bystanders cannot read your chat topics from your tab strip.
- **Decoy Title**: Default **`Google`** (editable to anything you prefer).

## Completion alerts

Open **Settings → Features → Alerts** to get notified when an AI finishes generating:

| Setting | Options | Default | Location & notes |
| --- | --- | --- | --- |
| **Desktop Notification / Completion Alert** | On / Off | **Off** (Extension) / **On** (Userscript) | Master switch for completion alerts (sound options below require this switch to be On). Extension builds request the optional `notifications` permission on first enable. On experimental macOS Safari, system notifications are unavailable so this switch controls sound alerts only. |
| **Notification Sound** | On / Off | On | Plays a built-in Web Audio chime when generation completes (active when the master switch above is On). |
| **Sound Preset** | **Default**, **Soft Chime**, **Glass Ping**, **Bright Alert** | **Soft Chime** | Includes an inline **Preview** button to audition each sound. |
| **Sound Volume** | 10%–100% | 50% | Adjusts notification audio loudness. |
| **Play Count** | 1 / 2 / 3 / 5 | 3 | **Advanced options** — Number of times the chime repeats. |
| **Repeat Interval** | 1 / 2 / 3 / 5 / 10 s | 2 s | **Advanced options** — Gap between repeated chimes. |
| **Notify When Focused** | On / Off | Off | **Advanced options** — Alert even when the AI tab is already in the foreground. |
| **Auto Focus Window** | On / Off | Off | **Advanced options** — Brings the browser window and tab to the front when generation finishes. Not supported on macOS Safari; userscript builds can only call `window.focus()` without unminimizing windows. |

## Advanced Model Usage Estimate

Also under **Settings → Features → Alerts**, Ophel includes a fully local counter and token estimator to help you pace rate-limited models:

| Setting | Options | Default | What it does |
| --- | --- | --- | --- |
| **Show usage estimate** | On / Off | Off | Mounts a compact status bar above the chat input showing today's send count, limit progress, and estimated request / round-trip tokens, with a manual **Reset** button. |
| **Daily send limit** | 1–9999 | 100 | Reference cap used to show progress and warnings at 80% and 100%. |
| **Reset automatically every day (Beta)** | On / Off | Off | Resets the local daily counter automatically each day. |

- **Usage History chart**: Built right into the card—filter by **All Sites** or **Current Site**, switch granularity between **Hour**, **Day**, and **Month**, and inspect 5 metrics: **Count**, **Request Tokens**, **Round Trip**, **Loaded Context**, and **Output Tokens**.
- **Estimate note**: Token counts are calculated locally from messages currently loaded in the page DOM using a lightweight character heuristic; they are rough planning estimates, not official platform billing numbers.
