## 站点扩展包与内置适配器有什么区别？

内置适配器可以包含处理复杂行为的站点专用 TypeScript。站点扩展包是声明式 JSON。

内置适配器优先级更高，不能被站点扩展包覆盖。已配置内置适配器的选择器修复走签名 patch 通道，而不是站点扩展包。

## 社区扩展包算官方 Ophel 代码吗？

registry 扩展包是经 Ophel registry 流程审阅并发布的社区贡献清单。它们使用相同的校验器与签名分发链，但支持的能力集合可能比内置适配器更窄。管理页会显示扩展包来源与声明能力。

## 为什么扩展会请求访问另一个域名？

在站点扩展包源上注册 content script 前，Ophel 需要可选主机权限。请求范围仅限扩展包引用的 HTTPS 源。拒绝后会回滚安装或绑定操作。

## 为什么油猴构建会要求我编辑 match 规则？

油猴管理器根据 `@match` 规则决定脚本可运行的位置。正在运行的脚本无法自行授予新的 match。因此 Ophel 会显示你需要在 Tampermonkey、Violentmonkey 或 ScriptCat 中添加的精确模式。

## 一个扩展包能支持多个自托管实例吗？

可以。扩展包可以使用空 `matches` 列表，这样它不会自行激活。然后在 **设置 → 站点扩展包 → 自定义站点** 中为每个 HTTPS 源绑定该扩展包。

Ophel 会按扩展包 ID 与源派生键存储每个实例，因此同一扩展包的两个部署不会混用设置、主题、阅读历史与会话。

## registry 扩展包会自动更新吗？

来自 registry 的扩展包会参与远程 registry 更新流程。客户端在应用更新前会检查签名索引、版本兼容性、不可变包哈希与运行时 schema。失败或无效下载不会替换 last-known-good 状态。

本地导入不会自动更新。若要替换，请导入更高版本的本地 JSON 文件。

默认检查间隔为 24 小时。

## 禁用或卸载扩展包会发生什么？

禁用会保留清单，但停止激活。卸载会移除清单及其注册引用。用户设置与会话数据会保留。

仅当没有已启用扩展包或自定义绑定仍引用该源时，才会移除源注册。

## 站点扩展包能运行任意 JavaScript 吗？

不能。站点扩展包会有意拒绝脚本、表达式、可执行回调、远程资源与不受限 CSS。需要命令式代码的复杂集成，必须作为内置适配器实现并审阅。

当前产品中不存在远程可执行 Site Pack / L3 代码插件路径。

## 会向 registry 发送哪些页面数据？

安装或更新 registry 扩展包时，只会向 CDN / GitHub 发起签名索引与包 JSON 的静态 GET 请求。这些请求不包含会话内容、提示词、Cookie 或页面 DOM。

向导中的可选 AI 选择器草稿助手也不会自动上传：只有在你复制时才会生成有界结构提示词，是否分享以及分享到哪里由你决定。

## 本地 JSON 导入安全吗？

本地导入仍会通过 Site Pack 校验器，因此未知字段与不安全声明值会被拒绝。但它们不会由签名社区 registry 认证。请检查目标域名与能力，并只从你信任的来源导入。

## 选择器失效了怎么办？

1. 确认扩展包已启用，且源仍然匹配。
2. 若扩展包来自在线库，检查是否有 registry 更新。
3. 对自托管扩展包，确认自定义源绑定仍然正确。
4. 若最新包仍失败，在 GitHub 提交 issue，附带站点 URL、Ophel 版本、扩展包版本与失效选择器名称。
5. 从报告中移除账号细节与私密会话内容。

## Ophel 会自动发现自托管域名吗？

不会。当前设计使用 **显式源绑定**。`matches` 为空的扩展包在你于 **自定义站点** 添加精确 HTTPS 源之前保持不激活。
