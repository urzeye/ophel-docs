站点适配包是纯声明式 JSON 清单，存放在主仓库 `ophel` 的 [`registry/sites/`](https://github.com/urzeye/ophel/tree/main/registry/sites) 目录下。

## 从示例起步

推荐复制 [`registry/examples/site-pack.example.json`](https://github.com/urzeye/ophel/blob/main/registry/examples/site-pack.example.json) 或参考结构相近的现有适配包（例如 [`registry/sites/duck-ai.json`](https://github.com/urzeye/ophel/blob/main/registry/sites/duck-ai.json)）进行修改。

### 最小合法清单示例

```json
{
  "schemaVersion": 1,
  "id": "example-chat",
  "version": 1,
  "minAppVersion": "1.2.5",
  "name": "Example Chat",
  "nameI18n": {
    "en": "Example Chat",
    "zh-CN": "示例对话"
  },
  "description": "Outline, export, prompts, and layout controls for Example Chat.",
  "matches": ["https://chat.example.com/*"],
  "capabilities": ["outline", "outline-user-queries", "export-basic", "prompt-insert"],
  "selectors": {
    "textarea": ["textarea[data-testid='prompt-input']"],
    "responseContainer": "main .messages",
    "userQuery": "[data-role='user']",
    "assistantResponse": "[data-role='assistant']",
    "scrollContainer": ["main"]
  },
  "input": {
    "mode": "textarea",
    "submitKey": "Enter"
  },
  "export": {
    "userQuerySelector": "[data-role='user']",
    "assistantResponseSelector": "[data-role='assistant']",
    "turnSelector": null,
    "useShadowDOM": false
  }
}
```

## Schema 与安全校验约束

运行时校验器（`src/adapters/declarative/validate.ts` 与 `registry/schema/site-pack.schema.json`）会强制检查以下规则：

- **`schemaVersion`**：必须为 `1`。
- **禁止 `$schema` 字段**：不要在清单中写 `$schema` 属性（会被严格校验拒绝）。
- **`id`**：小写字母、数字和连字符（`^[a-z0-9-]{2,40}$`），不得与任何内置站点或已有适配包重名。
- **`version`**：正整数，每次发布更新必须严格递增。
- **`minAppVersion`**：合法的语义化版本号，需不低于所用配置字段对应的最低 Ophel 版本。
- **`matches`**：在线库适配包最多 **10 条** `https://` 匹配规则；纯自部署应用留空数组 `[]`（安装后由用户在自定义站点绑定自己的 `http://` 或 `https://` 地址）。
- **`selectors`**：顶层必填对象。优先使用稳定的 `data-*`、`aria-*`、语义 HTML 标签或固定 ID，避免带构建哈希的 class 或依赖单一语言文案。
- **多语言文案**：建议补全 `nameI18n` 与 `descriptionI18n`（适配包 11 语种键名为 `zh-CN`、`zh-TW`、`en`、`ja`、`ko`、`it`、`de`、`es`、`fr`、`pt-BR`、`ru`）。
- **体积与安全限制**：
  - 序列化后的 JSON 必须 **≤ 64 KiB**。
  - 普通数组字段最多 **50 项**。
  - 所有正则表达式（如 `session.idFromPathRegex`）必须通过 `safe-regex2` 安全检测，防止回溯灾难。
  - 同源路径模板（如 `session.newTabPath`）必须以单个 `/` 开头。

各能力对应的字段要求与 `themeSync` 写法详见[能力参考](/zh/enhancements/site-extensions/capabilities)。

## 本地实测、校验与提交流程

<Steps>
  <Step title="在 Ophel 中本地导入实测">
    进入 **设置 → 适配中心 → 获取与更新 → 从文件安装适配包** 导入你的 `.json` 草案，授权目标域名并在真实对话页面逐项验证所声明的能力。
  </Step>
  <Step title="运行仓库校验命令">
    克隆 [urzeye/ophel](https://github.com/urzeye/ophel)，将文件保存为 `registry/sites/<id>.json`，执行：

    ```bash
    pnpm registry:validate       # 校验全部适配包 schema、正则安全与域名冲突
    pnpm registry:build          # 生成本地未签名产物用于联调
    pnpm registry:build:signed   # 生成带签名的发布产物
    ```
  </Step>
  <Step title="提交 Pull Request">
    提 PR 前对照 [`registry/README.md`](https://github.com/urzeye/ophel/blob/main/registry/README.md)、[`docs/developer/conventions/site-pack.md`](https://github.com/urzeye/ophel/blob/main/docs/developer/conventions/site-pack.md) 与 [Site Pack PR 模板](https://github.com/urzeye/ophel/blob/main/.github/PULL_REQUEST_TEMPLATE/site-pack.md) 完成检查。
  </Step>
</Steps>
